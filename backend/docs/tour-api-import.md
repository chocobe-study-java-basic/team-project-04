이 연결은 검수 전 후보 정보다. 실내외·시즌·현재 운영 상태는 응답이나 종목명으로 추정해 넣지 않는다. 추가 후보는 `TourImportTarget.initialFive()`의 명시적 목록을 검토해 확장한다.

## 로컬 실행 (PowerShell)

프로젝트 루트 `.env`에 `TOUR_API_KEY=일반 인증키(Decoding)`와 기존 MySQL 설정을 둔다. `.env`는 Git에서 제외되며 프런트엔드 환경 변수에 키를 넣지 않는다. Java 25와 실행 중인 Docker Desktop이 필요하다.

```powershell
docker compose up -d --wait --wait-timeout 180
powershell -ExecutionPolicy Bypass -File ./backend/scripts/import-tourapi.ps1
```

스크립트는 필요한 환경 변수만 읽고 Gradle `importTourPlaces`를 실행한다. 명령은 `local` 설정을 사용하는 별도 프로세스로, 웹 서버를 열지 않고 종료한다. 기존 8080 서버와 병행 실행할 수 있다. 일반 `bootRun`/서버 시작 및 CI 테스트에서는 외부 API를 호출하지 않는다. `.env`의 DB 호스트·포트가 의도한 로컬 DB인지 확인한다.

결과는 콘텐츠 ID와 `CREATED`, `SKIPPED`, `FAILED`로 표시한다. 일부 실패는 다른 후보와 격리하며 하나라도 실패하면 종료 코드 1을 반환한다. 원본 응답·인증키·요청 URL·원인 예외는 결과 로그에 포함하지 않는다.

## 저장 규칙

- 공식 `KorService2/detailCommon2`만 호출한다. 인증키는 한 번 인코딩하고 HTTP 리다이렉트를 따르지 않는다. 연결 제한 5초, 요청 제한 15초, 응답 최대 2MiB다.
- HTTP 성공뿐 아니라 제공기관 결과 코드, 콘텐츠 ID, 레포츠 유형(28), 예상 시설명, 주소·좌표·필드 길이·원본 수정일을 확인한다. 잘못된 응답은 저장하지 않는다.
- 홈페이지의 HTML 링크와 일반 텍스트를 HTTP(S) URL로 정규화한다. 소개는 일반 텍스트로 저장한다. 이미지·운영시간·요금은 수집하지 않는다.
- 장소와 종목, 출처, 수집 이력을 **한 장소 단위 트랜잭션**으로 저장한다. 항상 `DRAFT(0)`이며 공개 검색·상세에서 제외된다.
- 출처의 `origin_updated_at`은 제공기관의 수정일이다. 수집 이력의 `collected_at`은 서울 시간의 수집일이다. 운영자 검수일인 `verified_at`/`reviewed_at`은 비워둔다.
- `tour_api_import.content_id` 기본 키로 재수집을 방지한다. 저장 구간의 DB 잠금으로 동시 실행도 한 번만 저장한다. HTTP 호출 동안 DB 잠금을 유지하지 않는다.
- 재실행은 기존 장소를 덮어쓰지 않고 `SKIPPED` 처리한다. 운영자가 수정·공개한 정보도 유지한다. API 실패는 기존 데이터에 영향을 주지 않는다.
- 기존 지역·분류·종목은 재사용하고 수정하지 않는다. 수집 이력 없이 이미 존재하는 시설이나 서로 다른 콘텐츠 ID 간의 동일 시설 여부는 사람이 확인해야 한다.

## 공개 전 확인

현재 DB에 저장됐다는 사실만으로 사이트에 공개하지 않는다. 시설·종목 매칭, 주소·좌표, 공식 링크 및 소개 이용 조건을 검토하고, 확인한 항목의 출처와 검수일을 기록한 뒤 기존 장소 운영 흐름에서 공개한다. 대표 사진은 별도의 선정·권리 확인 정책을 따른다.

V4 마이그레이션은 수집 이력/잠금 테이블을 추가한다. 기존 V1~V3 및 공용 출처 테이블을 수정하지 않는다. 실패한 콘텐츠는 원인을 해결한 뒤 같은 명령을 재실행할 수 있으며, 이미 성공한 콘텐츠는 건너뛴다.

제공 서비스: [한국관광공사 국문 관광정보 서비스_GW](https://www.data.go.kr/data/15101578/openapi.do)

## 2026-11-16 로컬 초기 공개

`scripts/review-initial-tour-places.sql`은 이날 확인한 초기 5곳을 로컬에서 공개한 일회성 데이터 작업이다. 일반 수집은 계속 DRAFT로 저장하며, 이 SQL은 Flyway나 서버 시작에 연결하지 않는다. 운영자 관리 API·승인 이력 기능을 대신 구현한 것은 아니다.

- 웨이브파크: [공식 교통안내](https://www.wavepark.co.kr/trafficguide)로 도로명 주소를 대조했고, [공식 메인](https://www.wavepark.co.kr/main)에서 서핑 시설 안내를 확인했다.
- 곤지암: [공식 스키장 안내](https://www.konjiamresort.co.kr/ski/useInfo.dev)의 스키/보드 안내와 하단 주소를 대조했다. 홈페이지를 이 스키장 안내로 변경했다.
- 스카이라인 루지 부산: [공식 사이트](https://busan.skylineluge.kr/en/)에서 루지 시설과 홈페이지를 확인했다. 도로명 주소·좌표는 TourAPI 값을 유지하며 OFFICIAL 출처의 주소·좌표 검수 항목에는 포함하지 않았다.
- 정동진: [공식 시설 안내](https://www.railtrip.co.kr/kr/product_view.php?client_no=9)와 대조해 주소에 빠진 `강동면`을 보완하고, 통합 홈페이지를 시설별 안내 링크로 변경했다.
- 플라이스테이션: [공식 체험 안내](https://flystation.kr/usage/usage_020100.html)에서 종목과 주소를 대조했다. 접근 가능한 HTTPS 체험 안내로 홈페이지를 변경했다. 같은 페이지 내 체험 시간과 하단 운영시간도 차이가 있어 시간을 따로 저장하지 않았다.

소개는 확인한 시설 사실을 바탕으로 짧게 직접 작성했다. 원본 TourAPI 수집 출처는 미검수 상태로 보존하고, 별도의 OFFICIAL 출처에 실제 확인한 항목과 날짜만 기록했다. `verified_at`/`reviewed_at`은 날짜 단위 확인이라 2026-11-16 00:00:00으로 기록한다. `verifier_id`는 비어 있으며 팀 운영자 계정의 승인 이력이라고 주장하지 않는다.

기존 이름·주소·홈페이지가 수집 당시 값과 같은 미검수 DRAFT만 처리한다. 이미 공개했거나 다른 사람이 수정·검수한 장소는 건너뛴다. 한 트랜잭션으로 반영하며 재실행은 출처를 중복 추가하지 않는다. 로컬 실행에서 첫 회 5곳, 두 번째 0곳을 확인했다. 기존 가상 장소 6곳은 유지한다.

사진, 정밀 좌표의 독립 검증, 시즌·실내외 필터 값, 현재 운영 상태·요금은 아직 미확인이다. 따라서 시즌·실내외 필터를 선택하면 이 5곳이 검색 결과에서 빠질 수 있다.
