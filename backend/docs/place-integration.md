# 프론트와 장소 API 연결

## 브랜치와 조회 흐름

`feat/place-api-integration`에서 백엔드 `feat/place-model`에 프론트 `feat/#1-place-list-ui`를 병합했다. 원래 두 브랜치는 유지한다. 통합 브랜치에 프론트 연결, 필터 선택지 API와 demo 초기화를 추가했다. `develop`/`main`에는 아직 병합하거나 푸시하지 않았다.

브라우저 → `GET /api/v1/places/filters`로 선택지의 서버 ID 조회 → `GET /api/v1/places`로 목록/지도 검색 → `GET /api/v1/places/{id}`로 상세 조회.

- 선택지는 최상위 지역 ID/이름과 분류별 종목 ID 목록이다. 이름 없는 지역·분류는 제외한다.
- 공유 URL의 분류·지역 이름을 API 호출 시 조회한 ID로 바꾼다. 제공하지 않는 이름을 전체 검색으로 바꾸지 않고 빈 결과로 안내한다.
- 봄/여름/가을/겨울은 `SPRING/SUMMER/AUTUMN/WINTER`, 실내/실외는 `INDOOR/OUTDOOR`로 변환한다. demo와 연동 예시의 코드이며 실제 수집 데이터 변환 정책도 팀과 맞춰야 한다.
- 목록은 페이지당 20개다. 지도에도 같은 페이지의 장소만 표시하며 총 검색 결과 전체를 한꺼번에 표시하지 않는다. 화면에 이 범위를 안내한다.
- 좌표가 NULL인 장소는 목록·상세에만 표시하고 마커/길찾기에서 제외한다.
- 오류와 빈 결과를 구분하고 재시도를 제공한다. 취소 신호를 Axios에 전달한다. API 오류 때 프론트 샘플 데이터로 대체하지 않는다.
- 상세의 종목별 시즌·공지·확인된 출처는 서버 응답이다. 미확인 운영 정보는 미확인으로, 사진은 안내용 일러스트로 표시한다. 목록 API에 없는 설명·종목 요약을 임의로 만들거나 장소별 상세 요청을 추가하지 않는다.
- 공식 링크는 HTTP/HTTPS만 허용한다. 대표 사진·운영시간 저장 정책은 후속 작업이다.

## 로컬 실행

1. 루트 `.env`의 MySQL 설정으로 `docker compose up -d --wait --wait-timeout 180`을 실행한다. 3306을 다른 프로젝트가 사용하면 이 프로젝트의 `MYSQL_PORT=3307`을 유지한다.
2. IntelliJ BackendApplication의 환경 변수는 기존 MYSQL 설정을 사용한다. **Active profiles는 `local,demo`**로 실행한다.
3. 프론트 `.env.local`의 `NEXT_PUBLIC_API_BASE_URL=http://localhost:8080`과 기존 카카오맵 JavaScript 키 설정을 사용한다.
4. 루트 PowerShell에서 `npm.cmd --prefix frontend run dev`를 실행하고 `http://localhost:3000/`에서 확인한다.

`demo`를 지정하지 않거나 `prod`를 함께 활성화하면 demo 생성 코드는 실행되지 않는다. 명시한 개발 DB에만 사용한다. 운영 마이그레이션에는 demo INSERT를 넣지 않았다.

demo 초기화는 한 트랜잭션으로 가상 장소 6개·지역·종목·시즌을 저장한다. `OUTPICK-DEMO-V1` 지역 코드가 있으면 건너뛰어 순차 재실행 시 중복 생성되지 않는다. 기존 다른 장소를 수정하거나 삭제하지 않는다. 실제 시설이나 공공 API 데이터가 아니다. 이름의 `[데모]`, 가상 주소와 화면 문구로 표시하며 공식 홈페이지·확인된 출처·공지를 임의로 만들지 않는다. 프로필을 끈다고 이미 저장한 demo 데이터가 삭제되지는 않는다.

## 검증과 남은 작업

- Testcontainers에서 demo 6개 생성·재실행 시 중복 없음, 필터 ID API와 실제 검색을 검사한다. demo가 없는 기존 테스트는 별도 DB를 사용한다.
- 프론트는 MSW로 ID/코드/범위 직렬화, 오류/404 구분, 재시도, 좌표 없음 처리, URL 복원과 페이지 변경을 검증한다.
- 로컬 MySQL과 브라우저에서 목록 6개, 분류 필터 6→2개, 지도 서버 재조회 2→1개, 상세와 복귀를 확인했다.
- 공공 API 초기 후보 수집은 [TourAPI 수집 안내](tour-api-import.md)의 별도 명령으로 실행한다. 수집 결과는 검수 전이며 자동 공개하지 않는다. 초기 5곳은 별도 로컬 검수 SQL로 공개했고, 그중 4곳의 [대표 사진](place-images.md)을 연결했다. 일반 관리자 검수·공개 흐름 및 운영 배포/CD는 후속 작업이다.
