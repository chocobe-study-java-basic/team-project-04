# 미공유 장소 마이그레이션 번호 조정

회원 기능 V4~V6를 유지하기 위해 장소 후속 번호를 V7~V9로 옮겼다. SQL 본문과 V1~V3는 변경하지 않는다.

- V4: 회원 테이블 (#9).
- V5: 인증 버전 (#13).
- V6: 비밀번호 재설정 토큰 (#13).
- V7: `create_tour_api_import_tracking`.
- V8: `create_place_representative_image` (사진 브랜치).
- V9: `create_place_operating_info` (운영 정보 브랜치).

회원 → 재설정 → 장소 수집 → 사진 → 운영 정보 순서로 병합한다. 회원 PR이 병합되기 전에는 누락된 파일이나 성공 이력을 임의로 만들지 않는다.

## 개인 DB 처리

빈 DB는 평소처럼 실행한다. 예전 장소 V4~V6 또는 V5~V7를 적용한 개인 DB는 백업·복원을 확인한 뒤 별도로 이력을 맞춘다. 공유 DB에서는 사용하지 않는다.

회원 PR이 나중에 들어오면 개인 DB에는 낮은 V4~V6가 남는다. 내용을 검토하고 백업한 뒤 한 번만 `--spring.flyway.out-of-order=true`로 실제 SQL을 적용한다. 공통 설정·CI에 상시 켜지 않는다.

체크섬을 숨기기 위한 repair, 전체 이력 초기화, 테이블 삭제는 하지 않는다.
